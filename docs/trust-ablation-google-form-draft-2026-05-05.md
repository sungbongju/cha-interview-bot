### 7.2 Ablation Test 해석 방식

실제 기능 제거 버전을 여러 개 운영하기 어렵다면 설문 기반으로 다음 지표를 사용할 수 있다.

- 컴포넌트 기여도: D 섹션 각 문항 평균
- 제거 시 손실감: E 섹션 각 문항 평균
- 우선순위 지표: F1 선택 빈도
- 개선 필요도: F2 선택 빈도

컴포넌트가 신뢰 요인으로 강하다고 판단할 수 있는 조건:

- D 평균이 높음
- E 제거 시 손실감이 높음
- F1 선택 빈도가 높음
- 자유응답에서 반복적으로 언급됨

### 7.3 실제 Ablation 실험으로 확장할 경우

가능하다면 응답자를 몇 개 그룹으로 나누어 서로 다른 버전을 사용하게 하는 방식이 더 연구적으로 강하다.

| 그룹 | 제공 버전 |
| --- | --- |
| A 그룹 | 전체 기능 제공 |
| B 그룹 | 텍스트만 제공 |
| C 그룹 | 음성 제공, 아바타 없음 |
| D 그룹 | 아바타 제공, 세부 RAG 약화 버전 |
| E 그룹 | 상태 표시/토글 등 UI 신뢰 단서 제거 |

이후 그룹별 전체 신뢰도, 사용의도, 정보 이해도, 전공 선택 도움 정도를 비교하면 실제 Ablation Test에 가까운 설계가 된다.

## 8. 교수님께 보고 가능한 요약

구글폼은 단순 만족도 조사가 아니라, 선행연구 기반 18개 신뢰설계 컴포넌트가 실제 사용자 신뢰도에 얼마나 기여하는지 확인하는 구조로 설계하는 것이 좋겠습니다. 전체 신뢰도와 전공 선택 도움 정도를 먼저 측정하고, 이후 18개 컴포넌트별 신뢰 기여도, 해당 요소가 없을 때의 신뢰 손실감, 상위 3개 신뢰 요인을 함께 묻는 방식이 적절합니다.

실제 Ablation Test를 엄밀히 하려면 기능을 제거한 여러 버전을 그룹별로 제공하는 것이 가장 좋지만, 우선은 설문 기반으로 각 컴포넌트의 기여도와 제거 시 손실감을 측정하는 방식으로 시작할 수 있습니다.
