# 신뢰설계 컴포넌트 평가 설문 디자인 (v1)

**대상:** 박대근 교수님 보고용
**작성일:** 2026-05-05
**기반:** `survey-draft-v1.md` (교수님 초안) · `trust-components-map.html` (선행연구 기반 18개 컴포넌트) · `internal-survey-implementation-2026-05-05.md` (자체 DB 구현안)
**구현 상태:** 코드 완료, 학교 DB 마이그레이션 진행 중

## 1. 연구 목적

차의과학대학교 미래융합대학 신입생 전공상담 AI 면담봇(`cha-interview-bot`)에 적용된 **18개 신뢰설계 컴포넌트**가 사용자 신뢰도에 실제로 어떻게 기여하는지 검증한다.

선행연구로부터 도출한 18개 컴포넌트(박대근 교수 풀 디지털 트윈 ~ 카카오 인앱 외부 전환)는 4개 레이어로 구조화되며, 각 컴포넌트가 코드/UI상 어떤 기능과 1:1 대응되는지 매핑되어 있다. 본 설문은 이 매핑 위에서 사용자 인지를 측정하여, 어떤 컴포넌트가 신뢰를 만드는 핵심 요인인지 통계적으로 식별하는 것을 목표로 한다.

## 2. 설문 설계 원칙

| 원칙 | 채택 이유 |
| --- | --- |
| **단순 Yes/No 응답** | 5점 척도보다 응답 부담이 적고 완료율이 높다. 신입생 대상 4-5분 설문에 적합. |
| **18문항-18컴포넌트 1:1 매핑** | 컴포넌트별 신뢰 기여도를 직접 측정할 수 있고, 부록 매핑표만 보면 분석이 직관적이다. |
| **4-Layer 구조화** | 정체성/품질/자연스러움/정책의 4개 레이어로 묶어 점수 합산이 가능하며, 자유도 부족 문제를 회피한다. |
| **자체 DB 저장** | 구글폼 대신 학교 `cha_interview_db`에 저장하여 채팅 로그·사용자·세션과 조인 분석이 가능하다. |
| **익명 + 식별 옵션** | 로그인 사용자는 `user_id` 매핑, 비로그인은 `session_id`만 저장. 어느 쪽도 강제하지 않는다. |
| **조건부 문항 자동 처리** | 사용 모드/방문 횟수/접속 경로에 따라 비활성 + NULL 저장. 무관한 응답으로 인한 노이즈 제거. |

## 4. 응답 수집 방식

### 4.1 노출 시점

상담 종료(End 버튼 클릭) 시점에 모달이 자동으로 떠오른다. 단, **사용자 턴이 3회 미만이면 노출하지 않는다** — 짧은 체험은 응답 품질이 낮기 때문.

### 4.2 모달 구조

| 요소 | 설명 |
| --- | --- |
| 헤더 | 설문 제목 + "건너뛰기" 텍스트 링크 (X 버튼 대신, 부담 완화) |
| 안내문 | 익명·연구 목적·5분 소요 명시 |
| 진행 표시 | "응답 N/M" — 활성 문항 수에 따라 동적 |
| Yes/No UI | 가로 토글 버튼 2개 (모바일 친화) |
| 자유응답 | 선택 입력 (텍스트 영역 2,000자 제한) |
| 제출 | 인구통계 + 18문항 + Q24 모두 응답해야 활성화 |

### 4.3 조건부 문항 처리

| 문항 | 조건 | 미충족 시 처리 |
| --- | --- | --- |
| Q14 (Echo guard) | 음성/영상 모드 사용 | 자동 비활성, NULL 저장 |
| Q16 (아바타 입동기) | 영상 모드 사용 | 자동 비활성, NULL 저장 |
| Q21 (방문 횟수 추적) | 재방문자 (visit_count ≥ 2) | 자동 비활성, NULL 저장 |
| Q22 (TTS 발음) | 음성/영상 모드 사용 | 자동 비활성, NULL 저장 |
| Q23 (카카오 외부 전환) | 카카오톡 UA 진입 | 자동 비활성, NULL 저장 |

### 4.4 품질 보호 장치

- **소요시간 60초 미만**: `flag_too_fast=1`로 마킹 (분석 시 필터링 가능)
- **중복 제출 방지**: `session_id` + `user_id` 단위로 1건만 권장 (애플리케이션 레벨)
- **익명성 보장**: 이름·연락처 등 식별정보는 일절 수집하지 않음

## 5. 데이터 저장 구조

### 5.1 테이블

`cha_interview_db.survey_responses` (단일 wide-format 테이블)

### 5.2 주요 필드 그룹

| 그룹 | 필드 | 비고 |
| --- | --- | --- |
| 식별 | `user_id` (FK · NULL 가능), `session_id`, `survey_version` | 익명/비익명 모두 수용 |
| 인구통계 | `grade`, `gender`, `mbti`, `major1`, `major2` | Q1-Q5 |
| 18문항 | `q06_digital_twin` ~ `q23_kakao_redirect` | TINYINT(1), Yes=1/No=0/N/A=NULL |
| 전반 신뢰 | `q24_overall_trust` | Yes/No |
| 합산 점수 | `layer1_score` ~ `layer4_score`, `total_yes_count` | 서버 자동 계산 |
| 자유응답 | `free_positive`, `free_negative` | 선택 |
| 메타 | `user_agent`, `duration_seconds`, `flag_too_fast`, `submitted_at` | 응답 품질 분석용 |

### 5.3 자동 합산 점수

서버는 응답 저장 시 4-Layer 점수와 총합을 자동 계산해 별도 컬럼에 저장한다.

```
layer1_score  = sum(Q6-Q8)        ∈ [0, 3]
layer2_score  = sum(Q9-Q12)       ∈ [0, 4]
layer3_score  = sum(Q13-Q17)      ∈ [0, 5]
layer4_score  = sum(Q18-Q23)      ∈ [0, 6]
total_yes_count = sum(Q6-Q23)     ∈ [0, 18]
```

→ 분석 단계에서 매번 계산할 필요 없이 즉시 활용 가능.

## 6. 분석 계획

### 6.1 N=75 기준 권장 분석 (부록 B-1 반영)

18개 binary 예측변수를 동시에 단일 회귀에 넣으면 자유도가 부족하다. 다음 4가지를 단계적으로 적용한다.

#### (a) 기술통계 — 컴포넌트별 빈도

각 문항의 Yes 비율과 95% 신뢰구간을 보고. 어떤 컴포넌트가 사용자에게 "느껴졌는지" 직관 파악.

#### (b) 4-Layer 회귀 — 차원 축소된 모형

```
P(Q24 = Yes) = logit⁻¹(β₀ + β₁·L1 + β₂·L2 + β₃·L3 + β₄·L4)
```

각 레이어 합산 점수 4개를 예측변수로 사용. 자유도 충분, 어떤 레이어가 전반 신뢰의 핵심 동인인지 식별.

#### (c) 컴포넌트 × 전반 신뢰 — 카이제곱

각 컴포넌트(Q6-Q23) × Q24의 2×2 교차표에 대해 카이제곱 검정. 다중비교 보정(Bonferroni 등) 후 유의 컴포넌트 선별.

#### (d) 응답 패턴 클러스터링

18문항 응답 벡터를 기반으로 사용자 그룹화 (예: 모든 컴포넌트 Yes / Layer 1만 Yes / 등). 사용자 페르소나 도출.

### 6.2 인구통계 교차 분석

- 학년/성별/MBTI/전공별 컴포넌트 신뢰도 평균 차이
- 1전공 ↔ 2전공 조합과 컴포넌트 신뢰도의 상관

### 6.3 채팅 로그 결합 분석

`survey_responses`와 `chat_logs`를 `session_id`로 조인하여 다음 가능:

- 대화 턴 수와 신뢰도 상관
- 실제 사용한 모드(FTF/STS/TTT)와 컴포넌트 신뢰도 차이
- 자유응답 키워드와 18문항 응답 패턴의 텍스트-수치 결합 분석

### 6.4 Ablation 확장 (2차 예정)

본 설문(v1)은 가정형 Ablation을 포함하지 않는다. 1차 결과에서 핵심 컴포넌트가 식별되면, 2차에서는 해당 컴포넌트를 끈 변형 버전을 그룹별로 제공하여 실제 Ablation 효과 측정으로 확장한다.

## 9. 부록 B — 설문 문항 전문

### Part I. 기본 정보

- **Q1.** 학년 — 1/2/3/4/기타
- **Q2.** 성별 — 여/남/응답하지 않음
- **Q3.** MBTI (선택) — 16종 또는 모름/응답하지 않음
- **Q4.** 1전공 — 미래융합대학 11개 전공 중 1개
- **Q5.** 2전공 — 없음 또는 11개 전공 중 1개

### Part II. 봇 경험 평가 (18문항 · Yes/No)

#### Layer 1. 봇의 정체성

- **Q6.** 이 봇과 대화하면서 박대근 교수님 본인과 대화하는 듯한 느낌을 받았다.
- **Q7.** 이 봇이 차의과학대학교의 공식 도구라고 느껴졌다.
- **Q8.** 이 봇이 사람이 아니라 AI라는 점을 명확히 밝힌다고 느꼈다.

#### Layer 2. 답변의 품질

- **Q9.** 봇의 답변이 정확하고 사실에 근거한다고 느꼈다.
- **Q10.** 봇이 모르는 내용은 솔직히 "모른다"거나 "교수님께 직접 여쭤보세요"라고 안내했다.
- **Q11.** 봇의 말투가 따뜻하고 친근하게 느껴졌다.
- **Q12.** 봇의 답변 스타일이 일관되고 전문적이었다.

#### Layer 3. 대화의 자연스러움

- **Q13.** 봇과의 대화 호흡(질문 후 응답까지의 시간 등)이 자연스러웠다.
- **Q14.** 음성으로 대화할 때 봇 목소리와 내 목소리가 혼동되거나 어색하게 끊기는 일 없이 매끄럽게 진행되었다. *(음성/영상 모드 사용한 경우만)*
- **Q15.** 봇이 말하는 도중에 멈추고 싶을 때 멈출 수 있었다.
- **Q16.** 아바타의 입 모양과 표정이 자연스러워 보였다. *(영상 모드 사용한 경우만)*
- **Q17.** 영상·음성·텍스트 모드를 자유롭게 전환할 수 있는 점이 좋았다.

#### Layer 4. 정책과 관계 신호

- **Q18.** 회원가입 시 개인정보 처리 안내(수집 항목·이용 목적·보유 기간)가 명확하게 제시되었다.
- **Q19.** 로그인하지 않고도 둘러볼 수 있는 옵션이 부담을 덜어주었다.
- **Q20.** 봇이 "첫번째 방문을 환영합니다"처럼 자연스러운 한국어 표현으로 인사하는 점이 좋았다.
- **Q21.** 봇이 내 방문 횟수를 기억하고 인사하는 것이 친근하게 느껴졌다. *(2회 이상 방문한 경우만)*
- **Q22.** 봇이 영어 약어(AI, GPT 등)를 한국어 발음으로 자연스럽게 읽었다. *(음성/영상 모드 사용한 경우만)*
- **Q23.** 카카오톡에서 링크를 눌렀을 때 외부 브라우저로 자동 전환되어 편했다. *(카카오톡 접속한 경우만)*

### Part III. 전반적인 신뢰

- **Q24.** 전반적으로 이 봇을 신뢰할 수 있다고 느꼈다. (Yes/No)

### Part IV. 자유 의견 (선택)

- **Q25.** 봇을 사용하면서 가장 신뢰가 갔던 순간이나 기능은 무엇이었나요?
- **Q26.** 반대로 가장 신뢰가 떨어졌거나 어색했던 순간은 언제였나요?

## 10. 부록 C — 교수님께 드리는 요약

본 설문은 교수님께서 작성해 주신 `survey-draft-v1.md`를 그대로 채택하여 자체 DB에 저장하는 형태로 구현했습니다. 18개 신뢰설계 컴포넌트가 사용자 신뢰도에 미치는 영향을 측정하기 위해, 각 컴포넌트와 1:1 대응되는 Yes/No 문항을 4개 레이어로 묶었습니다.

샘플 크기 N=75 가정 시 단순 18-변수 로지스틱 회귀는 자유도가 부족하므로, **(a) 컴포넌트별 Yes 비율 기술통계**, **(b) 4-Layer 합산 점수 → 전반 신뢰 로지스틱 회귀**, **(c) 컴포넌트 × 전반 신뢰 카이제곱 검정**, **(d) 응답 패턴 클러스터링** 의 네 단계 분석을 단계적으로 적용할 계획입니다.

자체 DB 저장의 장점은, 설문 응답을 채팅 로그·사용자 정보·세션 메타데이터와 결합 분석할 수 있다는 점입니다. 단순 만족도 조사가 아닌, 신뢰 컴포넌트의 실제 기여도를 정량적으로 검증하는 연구 설계입니다.

본 v1 설문은 가정형 Ablation을 포함하지 않으며, 1차 응답 결과에서 핵심 컴포넌트가 식별되면 2차에서 실제 기능 차등 제공을 통한 그룹 비교 Ablation으로 확장할 계획입니다.
